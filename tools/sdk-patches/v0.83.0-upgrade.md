# SDK v0.83.0 compatibility review

The patched SDK is based on the public `v0.83.0` release, commit
`5593e887d7e014b214e998d9ff820b586ebf318f`. Generation uses Speakeasy
`1.806.0`, matching the release's workflow lockfile.

The SDK branch is `patch/v0.83.0/targeted-patch-defaults`, commit
`18b075cc1edda069f3a9cb2e6ab4d68605ba806b`. kongctl consumes it through the
replacement version `v0.83.1-0.20261105153347-18b075cc1edd`; this is a patched
v0.83.0 commit, not a v0.83.1 release.

## API versions

| API | Previous | Updated |
| --- | --- | --- |
| AI Gateway | 2.3.3 | 2.3.4 |
| Identity | 3.10.0 | 3.11.0 |

## Breaking and behavioral changes

- Identity key and identity-subtype discriminators move from single-value
  enums and exported fields to generated constant fields. For example,
  `KongPrincipalIdentityOIDC.Type` and its enum disappear. Use the union
  constructors and `GetType()` instead. The discriminator's JSON value is
  unchanged. kongctl has no references to the removed symbols.
- Token Vault credential subtypes similarly lose exported `CredentialType`
  fields and their single-value enums. Their getters now return strings.
  kongctl has no references to these removed fields or constants.
- `AuthStrategyClientCredentialsCredentialType` becomes `CredentialType`,
  with `CredentialTypeClientCredentials` and
  `CredentialTypeSelfManagedClientCredentials` constants. The old
  Token Vault `CredentialTypeShared` constant disappears; the shared name
  now belongs to the client-credentials enum. kongctl does not use these
  renamed symbols. Its separate generated E2E Portal client is unaffected.
- Identity CSV imports now document and generate `dry_run=true` by default.
  Callers must explicitly send `false` to apply an import. This documented
  default is retained; kongctl does not currently call this operation.
- Identity key/password request bodies now expose writable `expires_at`.
  Group names additionally allow internal hyphens. These are additive changes.
- AI Gateway changes add Terraform operation metadata for datastores; the
  generated Go datastore API signatures are unchanged.

## PATCH compatibility

The existing kongctl patch bundle still applies to this release. The new
Portal AI-settings PATCH models introduce defaults on optional MCP
`write_operations_enabled` and Portal Agent `display_name` and `audience`.
The added overlay removes those defaults so updating another field does not
overwrite omitted settings. Regression tests cover omission and explicit
values, including `false` and values equal to the API defaults.

The reviewed dump-default inventory records v0.83.0 and four new literal
`false` defaults under Portal `ai`. These describe the SDK's required
AI-settings fields; no default override or exclusion is needed.

Top-level `enabled` is required even on this PATCH endpoint. Required
enablement fields retain the upstream defaults. Portal Agent schemas are
shared with PUT requests, so those optional PUT fields also preserve omission.

## Scope assumptions and follow-up decisions

- This upgrade maintains existing kongctl functionality. New Portal
  navigation and AI-settings endpoints are available to SDK consumers;
  dedicated kongctl commands and declarative resource support need separate
  implementation. New Portal `ai` and create-time `theme_name` fields also
  need explicit planner, executor, and export support before being advertised
  as declaratively managed fields.
- Nullable Portal Agent fields and writable expiration fields use pointers
  in the generated SDK. They cannot distinguish explicit JSON `null` from
  omission. Supporting reset-to-null operations requires an upstream SDK
  change or a separately designed request representation. This upgrade does
  not assume that omitting these fields clears them.
- The AI-settings response schema gives `portal_agent` required field names
  without defining their properties or an object type. The generated
  `AISettingsResponseFeatures.PortalAgent` is consequently `any`. Strongly
  typed Portal Agent reads need an upstream spec correction; this upgrade
  preserves the published schema rather than inventing a response shape.
- Local validation excludes live E2E execution. CI E2E must confirm service
  behavior with the new spec. No replay scenarios or recordings are changed.

## Local validation

- kongctl: `go fix ./...`, `make format`, `make build`, `make lint`,

- All other `make test-all` targets pass: installer tests, patch-tool tests,
