# SDK v0.84.0 compatibility review

The patched SDK is based on public release `v0.84.0`, commit
`41c4ec7c`. Generation uses Speakeasy `1.808.1`, matching the release's
workflow lockfile. The SDK branch is
`patch/v0.84.0/targeted-patch-defaults`, commit `74edfa4c2948`.
kongctl consumes it through
`v0.84.1-0.20261111154937-74edfa4c2948`; this is a patched v0.84.0 commit,
not a v0.84.1 release. The bundle provenance records kongctl commit
`1ea50715df5f`.

The patched pseudo-version is a direct requirement rather than a replacement.
Go extension modules importing `pkg/sdk` therefore inherit that version
requirement. The example module records the same version without an SDK
replacement; CI builds it separately because root-module tests do not cover
nested modules.

## Breaking and behavioral changes

- No exported model fields or operation signatures were removed between
  v0.83.0 and v0.84.0. API document versions remain unchanged.
- `GatewayUnauthorizedError` and the five `KonnectCPLegacy*Error` types now
  return their message from `Error()` when available, rather than serialized
  JSON. kongctl's structured error attribute conversion now serializes those
  typed errors directly, retaining codes, messages, and details. Plain JSON
  error text still works. Displayed upstream error text can change from JSON
  to the message alone.
- Portal SAML updates now permit both metadata properties in the payload,
  with exactly one nonempty value. Empty strings count as absent. The URL
  pattern allows an empty string and the schema drops minimum string lengths.
  Go field types are unchanged. Existing kongctl request conversions remain
  compatible; this upgrade does not add a new SAML clearing convention.
- SDK JSON decoding gains internal opt-in preservation of untyped numbers as
  `json.Number`. It defaults to the previous `float64` behavior. kongctl does
  not enable the process-wide option.
- The generator adds an internal invalid-path-parameter error type. The
  release does not change URL generation to use it.

## PATCH compatibility and assumptions

The kongctl patch bundle remains the source of truth. All existing targeted
overlays, generated-code replacements, and wire regression tests are carried
forward. This includes Identity null/omission handling, cursor query encoding,
and preservation of omitted AI Gateway runtime settings.

The release introduces no new request defaults in its OpenAPI diff. The dump
default inventory changes only its SDK version, recording the exact patched
pseudo-version required by `go.mod`.

This upgrade preserves existing kongctl functionality and public SDK behavior
except for the established compatibility patches. No new API resource support
or backend contract is inferred. No maintainer intervention has been identified
from the source review; live service behavior remains subject to CI E2E.

Local validation excludes live E2E execution. Replay scenarios and recordings
are unchanged.

## Local validation

- SDK regeneration, compilation, and static analysis pass. OpenAPI lint has
  zero errors, with upstream warnings and hints retained.
- SDK patch wire regressions and model/internal/package tests pass.
  `make test.unit` passes with the race detector.
- kongctl `go fix ./...`, `make format`, `make build`, `make lint`,
  `make test`, and `make test-integration` pass. Integration tests use the
  existing mock configuration and retain existing guarded skips.
- Installer tests, patch-tool tests, E2E harness unit tests, E2E metrics
  tooling tests, and smoke-script tests pass. No live E2E scenarios ran.
- `make test-extension-go` passes with readonly module metadata. The example's
  `go mod tidy -diff` is empty and its selected SDK is the patched
  pseudo-version without an SDK replacement.
- Local Go gates used `GOFLAGS=-buildvcs=false` after automatic Go VCS
  stamping failed in this worktree. The build still uses the Makefile's
  explicit version/commit/date linker flags. The linter was v2.15.0.
- The generation snapshot is pushed under
  `refs/speakeasy/gen/12b5e172-3ee6-48a6-8aaa-016a703839e4` for subsequent
  regeneration. Linked worktrees need the release baseline snapshot fetched
  explicitly, as described in the patch guide.
