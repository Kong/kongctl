# SDK v0.86.1 compatibility review

The upgrade compares public release `v0.84.0` (`41c4ec7c`) and the current
patched commit `92b33d2ef4fd` with release `v0.86.1` (`1a17b97e`). It includes
the intervening 0.85 and 0.86 releases, not only the last patch release.
Generation uses Speakeasy `1.808.1`, matching the release lockfile.

## Approved removals

The maintainer explicitly approved accepting these upstream removals:

- Portal Navigation operations, SDK service, and models. kongctl had no
  command, helper integration, or declarative resource for these APIs.
- Portal AI Search and Portal Agent model fields. AI Search was exposed
  through embedded SDK models but absent from planner, executor, and export
  field mappings. Portal Agent had SDK PATCH regression coverage, but no
  kongctl declarative integration. Neither had full declarative support.
- Portal creation `theme_name`. It was exposed through the embedded SDK
  request model but absent from declarative field mappings.

These removals break the public Go SDK interface and previously accepted
model shapes. They do not remove working declarative reconciliation for the
removed features. The obsolete Portal Agent overlay targets and regression
cases are removed; MCP omission coverage remains. No E2E scenario or replay
recording is removed or changed.

## Other source changes under review

- Control-plane response cluster type, auth type, and cloud-gateway fields
  become pointers with API defaults. kongctl accesses them with nil guards,
  retaining empty-value handling and omitting false cloud-gateway on export.
- Consumer-group membership operations move under workspace paths, adding
  optional workspace selection. Removing all memberships now takes a request
  struct instead of separate identifiers. kongctl has no direct call to that
  operation.
- Many discriminator fields change from private generated constants to
  exported enum fields. Union constructors now populate the member's enum.
  SDK consumers constructing members directly must supply discriminators.
- AI Gateway MCP listener routes become required values instead of optional
  pointers. Several auth models are split into input/output forms. Existing
  kongctl JSON mapping must be checked against the generated types. The
  maintainer approved requiring explicit routes, aligning explain and affected
  fixtures without deriving route defaults.
- Role discovery response models are substantially expanded/restructured.
- Trusted IdP JIT mappings add `identifier` with a generated `sub` default.
  Upstream describes changing it as re-keying existing principal identities.
  The maintainer approved suppressing that default, preserving explicit
  values through normalization, and documenting the re-keying consequence.
- Event Gateway produce failure mode `mark` gains documentation explaining
  that failure details stored in record headers are visible to all consumers.
  The enum and kongctl behavior are unchanged.

## Scope

This upgrade does not infer new resource support from SDK availability or
introduce imperative write commands. Local validation excludes live E2E;
service behavior remains subject to CI E2E.
