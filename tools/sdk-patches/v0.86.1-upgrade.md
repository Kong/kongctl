# SDK v0.86.1 compatibility review

This upgrade can reject older configurations that omit an MCP route or include
removed Portal fields. It also changes the Go SDK interface. We updated
kongctl to handle the Go changes and keep existing supported behavior working.

The sections below name the API area and the endpoints or fields involved.
Removal from the spec or SDK does not by itself mean a feature was removed
from the Konnect product.

## Versions compared

The upgrade compares public release `v0.84.0` (`41c4ec7c`) and the current
patched commit `92b33d2ef4fd` with release `v0.86.1` (`1a17b97e`). It includes
the intervening 0.85 and 0.86 releases, not only the last patch release.
Generation uses Speakeasy `1.808.1`, matching the release lockfile.
The patched branch is `patch/v0.86.1/targeted-patch-defaults`, commit
`3db039d099b6`, consumed directly as
`v0.86.2-0.20261112224339-3db039d099b6`. This is a patched v0.86.1 commit,
not a v0.86.2 release. The bundle snapshot records kongctl commit
`fa49c327d327`.

The final v0.86.0-to-v0.86.1 source diff changes Event Gateway policy and
schema-registry descriptions, plus input OAS version metadata. The substantive
model/interface changes below come from the intervening releases.

## Breaking changes and their effects

### AI Gateway: MCP servers now need a route

The AI Gateway spec added `route` to the required fields inside `config`.
Older configurations that leave it out can now fail to load.

- API area: AI Gateway MCP Servers.
- Create endpoint: `POST /v1/ai-gateways/{gatewayId}/mcp-servers`.
- Update endpoint: `PUT` on the same path plus `/{mcpServerIdOrName}`.
- Field: `config.route`.
- Affected types: `listener`, `conversion-listener`, `passthrough-listener`,
  and `upstream-server`. `conversion-only` still allows omission.
- First sub-spec version with this change: **AI Gateway `2.3.5`**, after
  `2.3.4`. See [platform-api PR #3939][mcp-route-change]. This is the API spec
  version, not the SDK or Gateway runtime version.

For example, a user can supply `config.route.paths: [/mcp]`. The existing rule
still requires at least one nonempty matcher: `paths`, `hosts`, `methods`, or
`headers`. An empty `route: {}` is not enough. Kongctl does not choose a route
for the user. The maintainer approved this requirement and fixture updates.

### Developer Portal: AI Search and Portal Agent fields were removed

The spec and SDK no longer describe these settings:

- API area: Developer Portal AI settings.
- Endpoints: `GET`, `PATCH`, and `PUT` on
  `/v3/portals/{portalId}/ai-settings`.
- Removed AI Search field: `features.ai_search.enabled`.
- Removed Portal Agent fields: `features.portal_agent.display_name` and
  `features.portal_agent.audience` in the update request models.

AI Search also appeared in the embedded portal model as
`ai.features.ai_search.enabled`. Older kongctl manifests containing that field
can now fail to load. Kongctl previously accepted it through the SDK model,
but did not plan, apply, or export it as a managed setting.

Portal Agent had SDK patch tests, but no kongctl declarative integration.
Go programs using the removed SDK fields or types must change before they
can build. Portal MCP Server settings remain available.

The maintainer approved these removals. We removed the obsolete Portal Agent
patch targets and tests, while keeping MCP field-omission tests.

### Developer Portal: portal creation lost its theme field

The SDK removed the field for selecting a theme during portal creation.

- API area: Developer Portal creation.
- Endpoint: `POST /v3/portals`.
- Removed field: `theme_name` in the `CreatePortal` model.

An older manifest containing this field can now fail to load. Kongctl could
accept the field through its embedded SDK model, but did not apply it through
its declarative field mappings. Go code assigning that SDK field must also
change. This is separate from the supported Portal customization theme field.
The maintainer approved accepting the removal.

### Developer Portal: Navigation APIs were removed from the SDK

Go programs calling the old Portal Navigation SDK methods can no longer build
without changes.

- API area: Developer Portal sidebar navigation.
- Removed collection path:
  `/v3/portals/{portalId}/customization/navigations` (`GET` and `POST`).
- Removed item path: the same path plus `/{navigationId}` (`GET`, `PUT`, and
  `DELETE`).

Kongctl had no command, helper integration, or declarative resource for these
APIs. This therefore removes no working kongctl workflow. The maintainer
approved accepting the SDK removal.

### Several API areas: fixed type fields became Go enums

The SDK used to supply some fixed values automatically. It now exposes them
as typed Go fields. For example, an Event Gateway modify-headers policy used
to return the plain string `modify_headers` from `GetType()`. It now returns
the value of an enum field named `Type`.

- API areas include AI Gateway and Event Gateway.
- Fields include policy `type`, datastore `type`, and authentication `type`.
- Other changed getters include Portal custom-domain
  `ssl.domain_verification_method`.

Go code that expects a plain string needs a conversion such as
`string(policy.GetType())`. Code constructing a model directly must now set
its type explicitly. The SDK union constructors set the member type for their
callers. Existing kongctl tests now supply these values explicitly.

This also broke kongctl schema discovery: the old SDK tags told kongctl which
configuration shape belonged to each type. The maintainer approved a registry
of SDK enum constants to restore that knowledge. It keeps valid configurations
working; it does not fill in missing values or change outgoing requests.

### Control Planes: response fields now need absence checks in Go

The SDK changed three response fields from plain values to pointers. Go code
reading them must check whether a value is present before using it.

- API area: Konnect Control Planes.
- Endpoint: `GET /v2/control-planes/{controlPlaneId}`.
- Response fields: `config.cluster_type`, `config.auth_type`, and
  `config.cloud_gateway`.

We updated kongctl to handle absent values. Existing field projection and dump
behavior stay the same, including omitting false `cloud_gateway` on export.
This needs Go code changes, not manifest changes.

### Gateway Consumers: consumer-group membership paths changed

The spec moved consumer-group membership operations under workspace paths.

- API area: Control Planes Configuration, Gateway Consumers.
- Path prefix: `/v2/control-planes/{controlPlaneId}/core-entities/`.
- Old suffix: `consumers/{ConsumerId}/consumer_groups`.
- New suffix: `{workspace}/consumers/{ConsumerId}/consumer_groups`.
- Removing one membership also adds `/{ConsumerGroupId}` to that suffix.
- Affected operations: list memberships, add a membership, remove one
  membership, and remove all memberships.

The SDK now has optional workspace selection. Its remove-all method also
changed from separate identifier arguments to a request object. Go callers
using the old method signature must change. Kongctl has no direct call to
that remove-all operation.

### Identity: role discovery models changed

The SDK changed and expanded the Go objects returned when listing predefined
roles, including information for assignments covering multiple entities.

- API area: Konnect Identity, role discovery.
- Endpoint: `GET /v3/roles`.
- Affected SDK model: `Roles` and its nested role models.

Go programs referring to the old nested types or fields may need changes.
This upgrade does not add new kongctl role-assignment behavior.

## New field with an important behavior choice

### Kong Identity: choose the claim that identifies a principal

A Trusted IdP can now name the token claim used to recognize a principal, for
example `sub` or Microsoft Entra `oid`.

- API area: Kong Identity, Trusted IdPs within a directory.
- Create endpoint: `POST /v2/directories/{directoryId}/trusted-idps`.
- Replacement endpoint: `PUT` on the same path plus `/{trustedIdpId}`.
- Field: `jit.mapping.identifier`.

Adding the field is not itself a breaking change. Changing its value can make
existing principals stop resolving; later exchanges may create new principals
or fail authentication.

The new SDK automatically supplied `sub` when the field was omitted. The
maintainer approved removing that automatic value and keeping explicitly
supplied values. Our SDK patch and kongctl mapping code implement that choice.
This API replaces mappings, so omission does not promise to keep a remote
custom identifier. The service controls what omission means.

## Documentation changes without a new kongctl behavior

Event Gateway policy descriptions now explain more clearly what happens when
`failure_mode` is `mark` or `passthrough`. Relevant fields include produce and
consume policy `failure_mode`. A failure reason in a record header may expose
configuration details, and child field-processing policies do not run when
the parent cannot parse the record. The enum and kongctl behavior did not
change in this upgrade.

[mcp-route-change]: https://github.com/Kong/platform-api/pull/3939

## Schema discovery and defaults

The maintainer approved an explicit registry of SDK discriminator enum
constants. Go reflection cannot enumerate those constants, while the older
SDK exposed discriminator values through struct tags. Explain, loader
validation, and dump default branch selection use the same registry. This
describes schemas; it does not infer missing manifest values or change SDK
serialization. The registry covers enums reachable through resource models
and the custom model-provider schema. Future SDK upgrades must review it.

Portal theme omission is patched in both the existing inline schema and the
new standalone schema. All prior targeted request-presence regressions remain
except the approved obsolete Portal Agent cases. The defaults inventory gains
`access.acl_attribute_type: consumer` from the former constant selector and
loses the removed AI Search default. The former constant already serialized
`consumer`; this is a metadata representation change.

## Scope

This upgrade does not infer new resource support from SDK availability or
introduce imperative write commands. Local validation excludes live E2E;
service behavior remains subject to CI E2E.
