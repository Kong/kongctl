# SDK v0.89.0 compatibility review

The patched SDK is based on public release `v0.89.0`, commit
`c44c1524db6ac27e70661469ecdbc8effe9e09aa`. Generation uses the pinned
Speakeasy `1.808.1`. The SDK branch is
`patch/v0.89.0/targeted-patch-defaults`, commit
`3a5f81f45f5d11cd1e0aac0c9bbeda6722d9f664`, pushed to `origin`. kongctl
consumes it through `v0.89.1-0.20261119142615-3a5f81f45f5d`; this is a
patched v0.89.0 commit, not a v0.89.1 release. The bundle provenance records
kongctl commit `fd1c72097a29dcc732f42daa01decbb5260061ef`.

The gap from the previously consumed `v0.88.1-0.20261116190824-df9d11baeab7`
(a patched v0.88.0 commit) to `v0.89.0` is a single upstream commit
(`c44c1524`, "automated OAS update", #468), covering seven bumped input OAS
specs plus one new one:

| Input OAS | Old | New |
| --- | --- | --- |
| Konnect AI Cost Management | (new) | 0.10.0 |
| Konnect AI Gateway | 2.3.18 | 2.3.24 |
| Konnect API Catalog | 3.7.1 | 3.7.2 |

This is a much smaller gap than the v0.84.0 -> v0.88.0 upgrade (nine
commits). All findings below were confirmed directly against the generated
Go diff between the `v0.88.0` and `v0.89.0` tags and, for the one behavioral
change, against the originating `platform-api` PR.

## Breaking and behavioral changes

- **Portal OIDC identity-provider creation gained its own request schema,
  and now requires `client_secret`.** Confirmed directly against
  `platform-api`#4039 ("fix(portal): split OIDC IdP create config from
  shared config"): the create path previously reused the shared OIDC config
  schema, which incorrectly exposed `backchannel_logout` (unsupported on
  create) and left `client_secret` optional. The fix splits a dedicated
  `CreateOIDCIdentityProviderConfig` schema for creation, requiring
  `issuer_url`, `client_id`, and `client_secret`, and requiring at least one
  scope.

  On the Go side this deleted `components.PortalOIDCIdentityProviderConfigInput`
  and its union constructor, replacing them with
  `CreateOIDCIdentityProviderConfig` /
  `CreatePortalCreateIdentityProviderConfigCreateOIDCIdentityProviderConfig`.
  `ClientSecret` also changed from `*string` (optional) to `string` (required,
  no `omitempty`) on the new type. `internal/konnect/helpers/portal_identity_providers.go`
  referenced the deleted type and constructor directly — a compile break,
  fixed here by switching to the new type/constructor and an explicit
  `oidc.ClientSecret == nil` guard that returns a clear error instead of
  dereferencing a nil pointer. This mirrors the function's own existing
  style of per-type required-field checks (it already rejects a missing
  SAML/OIDC sub-config the same way); it adds no new declarative validation
  layer.

  **Needs intervention — not done here:** kongctl's own resource validation
  (`internal/declarative/resources/portal_identity_provider.go`) does not
  require `client_secret` for an OIDC portal identity provider. A manifest
  that omits it still loads and plans today, then fails at the helper's new
  guard (or previously, at the live API) when applied. Whether to add an
  earlier, resource-specific validation error (consistent with this repo's
  "required API fields must be explicitly stated" convention) is a product
  decision, not made here. The API now also requires at least one `scope`
  on create (`minItems: 1`); this has no Go type-level effect (still
  `[]string`) and was left unenforced client-side for the same reason.

  One test fixture (`internal/konnect/helpers/portal_identity_providers_test.go`,
  `TestPortalIdentityProviderAPIImplCreatePortalIdentityProviderIncludesExplicitEnabled`)
  predated the requirement and was updated to set a `client_secret`; its
  actual focus (explicit `enabled` presence) is unchanged.

- **New AI Gateway Model `datastores[].purpose` field, default
  `semantic-balancer`.** `AIGatewayModel`/`AIGatewayModelAPI`/`AIGatewayModelModel`'s
  `Datastores` field changed element type from `AIGatewayDatastoreRef` to a
  new `AIGatewayModelDatastoreRef`, which adds `Purpose *Purpose` (a
  single-value enum, `default:"semantic-balancer"`) alongside the existing
  `Name`. kongctl's own `AIGatewayDatastoreRef` usages (auth strategy,
  provider, MCP server, token vault) are unaffected — they still use the
  original type. Only the standalone `ai_gateway_model` resource type and
  the nested `ai_gateway.models[]` path are affected, and
  `AIGatewayModelResource` embeds `kkComps.CreateAIGatewayModelRequest`
  directly, so the new field rides along into kongctl's declarative shape
  automatically.

  This broke `TestAIGatewaySemanticDatastoreDumpRoundTrip`: a full dump of
  an `ai_gateway_model` round-tripped through the loader failed with
  `unknown field 'purpose'`, because the standalone resource's load schema
  is generated from its hand-maintained `explain` field list
  (`aiGatewayModelExplainNode` in `ai_gateway_model.go`), which only
  declared `name` for `datastores[]` items. (The nested `ai_gateway.models[]`
  path is unaffected — its explain node types `models` as an opaque object
  with no per-field schema, so it doesn't reject unknown fields.)

  **Fixed as part of this upgrade — mechanical schema-coverage fix, not new
  capability:** added `purpose` to the `datastores[]` explain field list as
  an optional, single-value-enum field (`explainConstStringNode("semantic-balancer")`),
  matching this repo's existing pattern for documented, literal API
  defaults. This only lets the already-embedded SDK field round-trip
  through the loader; it adds no new mutation path, since the field was
  already present via the SDK struct embedding regardless of the schema.
  Recorded in the dump-defaults golden inventory as
  `ai_gateway.models.datastores.purpose` / `ai_gateway_model.datastores.purpose`
  = `"semantic-balancer"`, source `sdk`.

- **`AIGatewayAgent.Type` and its enum constants renamed** (`Type` ->
  `AIGatewayAgentType`, `TypeA2a`/`TypeHTTP` ->
  `AIGatewayAgentTypeA2a`/`AIGatewayAgentTypeHTTP`) — a Speakeasy
  disambiguation rename, no schema change. Two test files referenced the
  old bare `kkComps.TypeA2a` constant directly
  (`internal/cmd/root/products/konnect/aigateway/agents_test.go`,
  `internal/declarative/planner/ai_gateway_agent_planner_test.go`) and were
  updated to the new name. No product code referenced it.

## Confirmed non-breaking (checked against actual kongctl call sites, not assumed)

- **AI Cost Management** — an entirely new OAS/API surface (budgets,
  exports, notification channels, usage events, attribution plugins)
  replacing the old, narrower `AIGatewayCostManagementTags` get/update
  operations, which are removed from the SDK entirely
  (`costmanagementtags.go`/`updatecostmanagementtags.go` and friends
  deleted). kongctl never called those operations — it only carries a
  `removedResourceTypeAICostManagementTags` string constant in
  `internal/declarative/planner/plan_compatibility.go` to reject *stale
  saved plans* that reference a resource type retired in an earlier
  release. Confirmed via `grep`: no other kongctl code references
  `CostManagementTags`. The new Cost Management API is simply not used.
- **`ListControlPlanesRequest.Sort`** changed from `*string` to
  `*components.ControlPlaneSortQuery` (platform-api#4067 constrained the
  sort query to an enum with validated bounds on `page[size]`/`page[number]`).
  None of kongctl's five `ListControlPlanesRequest{...}` call sites set
  `Sort`.
- **`ListGroupsQueryParamFilter.Type`** and
  **`ListIdentitiesQueryParamFilter.Type`** renamed to `QueryParamType` /
  `ListIdentitiesQueryParamType` respectively (disambiguation). Neither
  kongctl call site (`internal/konnect/helpers/identity_groups.go`,
  `identity_principal_identities.go`) sets the `Filter` field at all.
- **`AIGatewayMCPServerKongListenerConfig.URL`** (conversion-listener mode,
  request and response) changed from required `string` to optional
  `*string`. kongctl never literal-constructs this type directly.
- **`AIGatewayMCPServerRouteWithMatcher`'s anonymous union member** renamed
  from `Two` to `AIGatewayMCPServerRouteWithMatcher2` (disambiguation, no
  schema change). Not referenced by name in kongctl.
- **`PortalIdentityProviderConfig` / `PortalUpdateIdentityProviderConfig`**
  union types and constructors moved to a different generated file, with
  identical names — a pure code-location shuffle within the same package;
  Go doesn't care which file a package-level symbol lives in.
- Backchannel-logout documentation strings changed from
  `/api/v3/oauth/backchannel-logout` to `/api/v3/developer/backchannel-logout`
  — a doc-comment-only correction, no field or type change.

## PATCH compatibility and assumptions

All existing targeted overlays and generated-code replacements apply
cleanly against `v0.89.0`. The `identity-realms` omitzero patch and the OIDC
`upstream_access_token_header` patch continue to no-op / apply as they did
against `v0.88.0` (unaffected files). No new request defaults were
discovered in the OAS diff beyond `ai_gateway_model.datastores.purpose`
above, which is additive and schema-coverage-fixed rather than patched.
